# CODE_README — Regenerating and verifying the Pissta datasets

This kit reproduces every released dataset version from code + the frozen
paper-exact pickle. Expected runtime: **~6 min total** (2k verify ≈1 min; 5k
build ≈2 min; 10k build ≈4.5 min; OOD ≈seconds), CPU-only.

## 0. Environment

```bash
# either
python -m venv .venv && source .venv/bin/activate
pip install -r zenodo/requirements.txt

# or
conda env create -f zenodo/environment.yml && conda activate pissta-release
```

Exact versions the release was generated with are pinned in
`zenodo/requirements.txt` (Python 3.14.6, NumPy 2.4.0, torch 2.9.1,
torch-geometric 2.8.0.post1). Bit-exact float64 reproduction was verified on
this stack; other NumPy versions may differ in RNG stream or reduction order.

> MC label generation uses **CPU** sampling only — no CUDA build required.

## 1. Generate a dataset version

```bash
# Verify + publish the frozen paper-exact dataset (full 2000-graph MC
# label re-verification, splits check, then copy the frozen bytes):
python zenodo/scripts/generate_pissta.py --version pissta-2k

# Companion versions — REQUIRE the frozen pissta-2k pickle as prefix source:
python zenodo/scripts/generate_pissta.py --version pissta-5k
python zenodo/scripts/generate_pissta.py --version pissta-10k

# OOD companion (verify + publish the frozen Stage-7 eval set):
python zenodo/scripts/generate_pissta.py --version pissta-ood100
```

Outputs land in `zenodo/data/<version>/`:

| File | Contents |
|---|---|
| `dataset.pkl` | the dataset: per-graph structure, MC labels, physics features |
| `splits.json` | stratified train/val/test graph-id lists (2k/5k/10k only) |
| `summary_stats.json` | dataset-level label/structure statistics (2k/5k/10k) |
| `manifest.json` | process constants, commit hash, config snapshot, SHA256 of every file, disclaimers, provenance notes |

Options: `--seed-2k PATH` (prefix source, default
`data_generation/data/dataset.pkl`), `--out-dir PATH` (default
`zenodo/data`), `--smoke` (50 extension graphs, writes to
`zenodo/data-smoke/`, marked non-citable in its manifest).

## 2. Verify the release

```bash
python zenodo/scripts/verify_release.py                     # all versions
python zenodo/scripts/verify_release.py --version pissta-5k # one version
```

Checks (exit code non-zero on any failure):

- **H1** manifest SHA256 hashes match the published files
- **H2** every pickle unpickles with the documented schema
- **H3** `summary_stats.json` recomputes from `dataset.pkl`
- **H4** manifest counts match; splits are a true partition
- **R1** stratified splits regenerate bit-exactly from the frozen procedure
- **R2/R3** sampled MC labels recomputed **bit-exactly** (N=10k, seed 42)
- **N1** nesting: all 2,000 prefix entries byte-identical across 2k ⊂ 5k ⊂ 10k

Each dataset directory gets a `VERIFICATION.txt` summary. Upload it next to
the data (see the Zenodo checklist below).

### Full-regeneration check (optional, recommended once before upload)

```bash
# Regenerate 5k/10k into a scratch directory, then content-compare:
python zenodo/scripts/generate_pissta.py --version pissta-10k --out-dir /tmp/regen
python zenodo/scripts/verify_release.py --version pissta-10k --compare /tmp/regen
```

Byte equality holds for the frozen-verbatim datasets (pissta-2k, ood100). For
extension builds, `--compare` checks **content equality** of everything except
`wall_time_s` timing metadata (and manifest timestamps): structures, MC labels,
physics features, splits, and summary stats must match exactly. A content
match is the pass criterion — wall-time noise is expected and harmless.

## 3. What "reproduces" means (read before citing)

- **pissta-2k** is a *frozen artifact* — the generator **verifies** it
  (structure regeneration from seed 42, full 2000-graph bit-exact MC label
  recomputation, split regeneration) and then publishes the original bytes.
  It never rebuilds it: the build's gate-load value→gate pairing depended on
  the build process's `PYTHONHASHSEED` (Python set iteration order) and is
  part of the artifact. Load **values** are hash-order independent and
  bit-exact; only which gate received which draw is frozen. See
  `structure_build_note` in the 2k manifest.
- **pissta-5k / pissta-10k** are *built* from `--seed-2k` + seed 42:
  - graphs 000000–001999: verbatim 2k entries (nesting is machine-checked);
  - graphs 2000+: generated by the current generator with a canonical,
    process-independent load pairing (ascending load value → lexicographic
    gate name). Deterministic on any machine given the pinned environment.

If `verify_release.py` passes, a reader can hold the released bytes to the
same standard as a fresh run: the supervised labels are recomputable to the
bit, the split procedure is re-derivable, and the file hashes pin the artifacts.

## 4. Zenodo upload checklist

1. Run the generator for all four versions, then `verify_release.py` — all
   checks green.
2. Reserve a DOI (Zenodo → New upload → reserve DOI) and record it in
   `.zenodo.json` at the repo root before tagging the code commit.
3. Recommended: **separate deposits** — one code deposit (the repo, MIT) and
   one deposit per dataset version (CC-BY-4.0), each `dataset.pkl` +
   `splits.json` + `summary_stats.json` + `manifest.json` + `VERIFICATION.txt`.
4. If you must upload a single archive: dual-license the deposit
   (MIT code + CC-BY-4.0 data) and state the split in the description.
5. Link the dataset deposits to the code deposit (and vice versa) via
   "related identifiers"; cite the concept DOI in the paper.
6. Keep the *smoke* artifacts out of the deposits (non-citable by
   construction, repo hardening convention N2).

## 5. Manifest fields worth knowing

| Field | Meaning |
|---|---|
| `process_constants` | seeds, `mc_n_samples`, gate ranges, split fractions, sampler provenance |
| `generator_commit` | repo commit the release scripts ran against |
| `config_snapshot` | full `foundations/stage3_config.json` at build time |
| `disclaimers` | toy-model + emulation statements (keep visible in the paper) |
| `structure_build_note` | the 2k PYTHONHASHSEED pairing caveat |
| `extension_provenance.load_pairing` | the canonical rule used for graphs 2000+ |
| `regeneration` | what was re-verified at publish time |
| `files` | SHA256 + byte size of every published file |

## 6. Troubleshooting

- **`ABORT: seed pickle must be the frozen pissta-2k`** — you pointed
  `--seed-2k` at something other than the 2000-graph frozen pickle.
- **`ABORT: prefix structure mismatch`** — the repo's
  `data_generation/graph_generator.py` drifted from commit `d697021`
  (`generator_commit` in the manifest). Check out that commit or bisect.
- **Label mismatches in R2/R3** — environment drift (NumPy version). The
  released environment is pinned in `zenodo/requirements.txt`; rerun there.
- **Unicode/float warnings when comparing JSONs** — cosmetic only; the
  verifier compares parsed values, not raw bytes, for generated JSON.
